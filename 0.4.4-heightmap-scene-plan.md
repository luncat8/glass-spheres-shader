# Plan 0.4.4 — heightmap scene: a piece of glass landscape

From `0.4.3-object-shape-mesh-draft.md`, second half: a new scene where a
simplex heightmap is constrained to the **top face of a cube**, plus a second
mesh for a **lake**, so the result reads as a piece of landscape made of glass.
The draft asks for two looks:

* **A — all glass.** Heightmap cube drawn with the selected shader's glass, lake
  in blue-tinted glass. A transparent landscape floating in the sky.
* **B — opaque land, glass water.** Heightmap cube in a solid height-colourised
  material (rock → grass → snow), lake drawn as glass water. A landscape you can
  read topographically, with the water doing the refracting.

Both are one scene with a style switch, not two scenes: *where* the objects are
and *how* they move is identical, only the land's material differs.

## Model — scene `terrain`, `uScene == 4`

| | |
|---|---|
| id / label | `terrain` / `glass land` |
| `uScene` | 4 |
| native shader | `analytic_layers` (the only renderer that composites world geometry at its measured depth) |
| environment | the existing pastel sky |
| motion | objects drift above the ridge line, inside the cube's footprint |
| world geometry | land cube with a simplex-displaced top face + lake slab, both finite |

Adding the value 4 is inert until the land block opts in, which is what makes
this scene cheap: every scene-gated branch in the codebase compares
`uScene == 3` (`js/scene.js` feeds, `js/camera.js` cage picking,
`GLSL.cageOverlay`, `analytic_layers`' wire pass), and `GLSL.env`'s dispatch ends
in `if (uScene >= 3) return envPastel (d);` — so `terrain` inherits the pastel
sky with no change, which is exactly right: the land cube *is* the ground, so the
scene must not also draw `envChecker`'s infinite plane at `y = -3`.

A new `GLSL.landOverlay` block mirrors the `GLSL.cageOverlay` precedent: the
shared scene owns the world-space geometry, the material renderer keeps drawing
its own objects, and the block is a no-op unless `uScene == 4`.

## Geometry

### Land — a cube with a displaced top

```glsl
// h = fbm of 2D simplex over the footprint, amplitude uLandAmp, frequency uLandFreq
float landHeight (vec2 xz);

// the solid is the intersection of the cube and the half-space below the
// heightfield, so the sides and bottom stay flat cube faces and the landscape
// reads as a finite piece of terrain rather than an infinite plane
float sdLand (vec3 p) {
	float box = sdBox (p, vec3 (uLandSize, uLandSize, uLandSize));
	float top = (p.y - landHeight (p.xz)) * LAND_LIPSCHITZ;
	return max (box, top);
}
```

`p.y - h(xz)` is not a distance: its gradient is `√(1 + |∇h|²) > 1`, so
sphere-tracing it raw over-steps and eats surface detail (and can tunnel). The
noise is band-limited — with `uLandAmp`/`uLandFreq` bounded by the sliders,
`|∇h|` has a known maximum — so one conservative constant
(`LAND_LIPSCHITZ ≈ 0.5`, derived in the block from the worst-case slope, not
guessed) makes the field safe to march. The rejected alternative is heightfield
marching in the ray parameter (step `t`, compare `ray.y` with `h`): robust for
primary visibility, but it needs a sign change, so it fails for rays that start
inside or below the terrain — which reflection and refraction rays routinely do.

### Lake — the water column, not a water sheet

```glsl
float sdWater (vec3 p) {
	float box = sdBox (p, vec3 (uLandSize, uLandSize, uLandSize));
	return max (box, (uLakeLevel - p.y) * WATER_LIPSCHITZ);
}

// id 0 = land, 1 = water; marched together, nearest surface wins
vec2 landMap (vec3 p);
```

The water is the region of the cube *below* the lake plane, not a thin slab.
That choice is what makes it look like water: a ray that enters the lake keeps
travelling until it reaches the submerged terrain, so the chord length
`level - h(p)` drives Beer-Lambert absorption and the shallows stay pale while
the deeps go blue-black. A thin slab cannot do depth, and its underside
z-fights with the terrain it is supposed to cover.

Both solids overlap below `min(h, level)`; `landMap` returns the nearer surface
with its id, and the land is drawn *through* the water column when the water
surface is what got hit.

### Simplex

`GLSL.simplex` — self-contained 2D simplex gradient noise plus a 3-octave fbm
wrapper (Ashima/iq formulation, permutation by hashing, no texture, no library,
no internet; AGENTS.md forbids all three). The existing `swirl()` is a
sin-product wobble, not noise: too regular for terrain silhouettes and it would
band on the ridge line. The land is time-independent by default (`uLandDrift`,
default 0, for a very slow erosion-style drift), because a landscape that
wobbles stops reading as landscape.

## Material

The land is shaded by the overlay, not by each renderer, following
`cageShadeTop` (which already draws "generic opaque top balls" inside glass
shaders rather than asking five renderers for five hooks).

* **style 0 — glass land** (`uLandStyle == 0`): one refraction into the solid,
  Fresnel-weighted `envSun` reflection on top, Beer-Lambert over the interior
  chord with a faint green-cyan tint, caustic-free. Water: the same model with a
  blue tint (`WATER_TINT`) and its own absorption.
* **style 1 — colour land** (`uLandStyle == 1`): height- and slope-colourised
  opaque material (deep shore → grass → rock → snow by `h` and by
  `1 - n.y`), diffuse sun plus a small `envSun` ambient, and the lake stays the
  glass water of style 0.

`uLandStyle` is an `options` param gated with `"scenes": ["terrain"]`, so it
renders as a `<select>` in the existing parameter strip and disappears in every
other scene — no new UI machinery.

**Optional per-shader hook.** A shader that wants its own glass on the land
defines `LAND_HOOK` before interpolating the block and provides

```glsl
vec3 landShade (vec3 behind, vec3 ro, vec3 rd, vec3 p, vec3 n, float id);
```

The block wraps its own shading in `#ifndef LAND_HOOK`. `analytic_layers`
(`shadeGlass`) and `hollow_bubbles` (`crossWall`) are the two candidates; the
default generic glass is what ships first, so no renderer is blocked on it.

## Depth composition with the objects

The land is world geometry that can be in front of or behind the drifting
objects, so it must be composited at its measured depth — not painted over the
final colour. The block therefore takes the shader's nearest object depth:

```glsl
vec3 landOverlay (vec3 behind, vec3 ro, vec3 rd, float objT);   // objT = BIG if unknown
float landHitT (vec3 ro, vec3 rd);                              // BIG on a miss
```

`landHitT < objT` → the land wins the pixel; otherwise the objects stay on top.
Every renderer already computes a first-hit `t` internally (`h0.t` in
`analytic_layers`, the march result in `thick_raymarch` / `thick_chain`, the
first membrane event in `hollow_bubbles`, the sorted layer in
`thick_analytic`), so passing it costs one variable. The wire cube stays
cage-only; the two overlays are mutually exclusive by scene.

## Motion — objects above the ridge line

The scene owns motion, so `js/scene.js` gains a terrain branch in the existing
scene-aware feeds (`bubbles`, `bubbles61`, `sceneBubbles4`):

```js
// x/z scaled into the cube footprint, y lifted clear of the ridge line
function feedAboveLand (c, time, meta, out) { ... }
```

**Simplex is not reimplemented in JS.** Exact per-object ground clearance would
need the same noise on both sides — duplication, and a drift hazard. Instead the
feed uses the conservative bound the sliders already give: objects are placed in
`y ∈ [uLandBase + uLandAmp + gap, … + ceiling]`, which is above every possible
ridge. Same trick as the cage's `cage - radius` bound. The `mov: off` toggle and
`uSpread` / `uSize` keep working unchanged; `uTopCount` / `uGravity` stay
cage-only.

Picking is untouched: the objects are still spheres from the same feeds, and the
land is deliberately not pickable — clicking it misses, which already deselects.

## Camera

The land cube (`uLandSize` 3…10) is much bigger than the cage (2…4.5), so the
default `dist = 7.5` starts inside the landscape. Scene entries gain optional
framing:

```js
{ id: 'terrain', label: 'glass land', uScene: 4, native: 'analytic_layers',
  camDist: 16.0, camPitch: 0.30, hint: '...' }
```

`Cam.attach()` (already called by `ui.pickScene` and `ui.pick`) applies them when
present and leaves the camera alone when absent, so no existing scene changes.
`MIN_DIST` / `MAX_DIST` (2.2…40) already cover it, and the 0.4.2 viewport-relative
grab drag needs no adjustment: a bigger subject is framed by zooming out, not by
a different turn rate.

## Parameters (all `"scenes": ["terrain"]`)

| param | type | range | default | meaning |
|---|---|---|---|---|
| `uLandSize` | float | 3.0 … 10.0 | 5.0 | cube half-size = the footprint of the landscape |
| `uLandAmp` | float | 0.2 … 3.0 | 1.1 | ridge amplitude above the base height |
| `uLandBase` | float | -2.0 … 2.0 | 0.0 | height of the flat base plane the relief sits on |
| `uLandFreq` | float | 0.05 … 0.6 | 0.18 | simplex frequency (feature size) |
| `uLakeLevel` | float | -1.5 … 1.5 | 0.15 | water plane height; valleys below it fill |
| `uLandStyle` | options | glass / colour | glass | look A or look B |
| `uLandSteps` | int | 32 / 64 / 96 | 64 | march budget for the land |
| `uLandDrift` | float | 0.0 … 0.3 | 0.0 | slow time drift of the heightfield |

`uScene` stays hidden and owned by the scene row, exactly as today.

## Cost, and how it is kept down

The land march is the most expensive world geometry in the project:
`uLandSteps` × 3-octave simplex per ray, on every primary ray, in addition to
whatever the material renderer does.

1. **Analytic bounding-box pre-test.** One ray/box test against the land cube
   rejects the sky and most of the frame before a single noise evaluation —
   typically > 60 % of pixels on a centred shot.
2. **Primary rays only.** Reflection and refraction rays sample `envSun` for the
   land instead of re-marching it (the same simplification `cageOverlay` makes
   for the wire cube). Multi-bounce renderers therefore pay the land once.
3. **`uLandSteps`** for integrated GPUs, defaulting to 64; the global `aa`
   button already caps SMAA at 2K and the shader-level `uAA` stays opt-in.
4. The overlay is compiled only into the five scene-aware shaders, and only
   reaches the noise when `uScene == 4`.

## Validation

* **glslang type-check** of the assembled fragment source for all five renderers
  × all six scenes, as in 0.3.x/0.4.3.
* **`tools_GPU/check-land.mjs`** (headless, no GPU): the JS side of the contract —
  * `feedAboveLand` output is finite, inside the footprint
    (`|x| , |z| ≤ uLandSize · spread`) and above the conservative ridge bound
    (`y ≥ uLandBase + uLandAmp + gap`) for every index, time and slider corner;
  * the bound is monotone in `uLandAmp` / `uLandBase`, so no slider combination
    can push an object into the terrain;
  * `LAND_LIPSCHITZ` is ≤ `1 / √(1 + maxSlope²)` for the worst-case slider
    corner, computed from the same octave/amplitude/frequency table the GLSL
    uses (the constant is generated from a JS table, as in 0.4.3, so it cannot
    drift);
  * a JS reference implementation of the fbm is bounded by `uLandAmp` over 10⁵
    samples — the "conservative bound" the motion feed relies on.
* **`tools_GPU/check-ui.mjs`** extended: 11 shaders × 6 scenes select without
  error; `terrain` is `alt` for the six own-camera shaders and switching to it
  moves the shader to `analytic_layers` with a note; the land sliders appear only
  in `terrain` and `uLandStyle` renders as a `<select>`; picking the scene
  applies `camDist` / `camPitch` once and leaves the other scenes' camera alone.
* **Browser**: look A reads as a transparent glass landscape with visible
  submerged terrain through the lake; look B reads topographically with glass
  water; the ridge line is smooth at 4K with `aa` on (no marching stair-step);
  objects never intersect the terrain in any scene time; fps at 1080p and 4K on
  the five renderers with `uLandSteps` 32/64/96.

## Out of scope

* heightmap assets, textures, real DEM data — the terrain is procedural;
* water simulation, waves, gerstner normals, foam, caustics and screen-space
  reflections (a `uWaterRipple` normal perturbation is the most that may be
  added later);
* an infinite or chunked/LOD terrain — the point is a finite piece of landscape;
* terrain collision or resting contact for the objects (they float above it);
* picking the land, and any land-driven camera framing beyond `camDist` /
  `camPitch`;
* teaching the own-camera shaders and the Shadertoy originals this scene — the
  same "difficult to implement, so skip" rule as everywhere else in the project.
