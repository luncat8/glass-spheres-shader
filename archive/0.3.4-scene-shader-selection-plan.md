# Plan 0.3.4 — split "shader" and "scene" into two independent selectors

## Problem

The toolbar had one row of shader buttons; the *scene* lived inside each
shader's parameter strip as a `scene` dropdown. That produced four separate
confusions:

1. **`cage` was both a shader and a scene.** `shaders/cage.js` appeared in the
   shader row while `cage` also appeared in the scene dropdown of four other
   shaders. Two different things with one name.
2. **The scene was per-shader state.** Each shader's `uScene` param kept its own
   value, so switching shader silently reset the scene back to `checker land`
   (or to whatever that shader was last left on). The user's scene choice did
   not survive a shader change, and vice versa.
3. **Dead sliders.** `cage`, `wire`, `gravity`, `on top` were visible in every
   scene, but did nothing outside the cage scene.
4. **No signal about incompatibility.** Nothing said which shader could draw
   which scene, so the missing combinations just looked broken.

## Model

Two orthogonal choices, one selector each, both global:

| | question it answers | examples |
|---|---|---|
| **shader** | *how* the bubbles are drawn | membrane tracing, analytic layers, raymarched SDF, chain refraction |
| **scene** | *where* they are drawn and *how* they move | checker land, rainbow, color box, cage (wire cube + elastic bounce + balls on top) |

The scene owns both the environment **and** the motion model, because "cage"
means "bounce inside a box", not just "pastel sky".

### Compatibility

Independent wherever it is cheap. A shader declares what it can render:

```js
window.SHADER_x = { id: 'x', scenes: ['checker','rainbow','colorbox','cage'], nativeScene: 'checker', group: 'scene', ... }
```

- `group: 'scene'` — scene-aware; declares the hidden `uScene` uniform and reads
  its spheres from a scene-aware feed.
- `group: 'own'` / `group: 'orig'` — cubemap-only or original Shadertoy ports.
  Their camera and material pipelines cannot express the shared scenes, so they
  declare `scenes: ['own']` and keep their built-in look. Porting them is
  explicitly *not* worth it (the "difficult to implement" case).

When a combination does not exist, **the selector the user just clicked wins**
and the other one falls back to its native partner, with a note in the toolbar
saying exactly what happened:

```text
pick a shader that cannot do the current scene -> scene  := nativeScene(shader)
pick a scene that the current shader cannot do -> shader := nativeShader(scene)
```

`own` is never a fallback target: it is not a scene you choose, it is what you
get when the chosen shader brings its own. Its button is disabled (with a
tooltip) while a scene-aware shader is selected.

## Changes

| File | Change |
|---|---|
| `js/scenes.js` | **new** — scene registry (`own`, `checker`, `rainbow`, `colorbox`, `cage`), `supports` / `nativeScene` / `nativeShader` / `apply` / `paramVisible` |
| `js/ui.js` | two labelled selector rows; global `curScene`; fallback notes; scene-filtered parameter strip; `__app.setScene` / `scene` / `scenes` |
| `index.html` | `shader · how it draws` and `scene · where + motion` rows, grouped shader buttons, `alt`/disabled button styling, load `js/scenes.js` |
| `shaders/cage.js` → `shaders/analytic_layers.js` | renamed: it is a *draw style* (nearest-3-layer analytic glass, up to 61 spheres), not a scene. `#define uScene 3` becomes a real uniform, `envPastel` becomes `env`, the wire cube and top balls are gated on `uScene == 3`, so it now works in all four scenes |
| `shaders/hollow_bubbles.js`, `thick_analytic.js`, `thick_chain.js`, `thick_raymarch.js` | `uScene` dropdown replaced by a hidden `uScene` param; `scenes` / `nativeScene` / `group` metadata; cage-only sliders gated with `"scenes": ["cage"]`; `uSpread` added to the thick trio so their strip is not empty outside the cage |
| `shaders/*` (originals) | `scenes: ['own']` + `group` metadata |
| `js/scene.js` | new scene-aware `bubbles61` feed (61-sphere cloud ⇄ cage bounce); `sceneBubbles4` honours `uSpread` |
| `js/camera.js` | pickable/selection generalised over a `MAIN_FEEDS` table instead of hard-coded feed names; the dead `fixed4` mirror removed |
| `js/prompts.js` | `cage` entry renamed to `analytic_layers` |

Switching the scene **never recompiles**: the shader already declares `uScene`
and its feed is scene-aware, so only the param value, the visible sliders and
the selection are refreshed. Switching the shader recompiles as before and
re-applies the current scene before the first frame.

## Param visibility

A param may declare `"scenes": [...]` to restrict itself to some scenes; the
strip filters on that. `uScene` is `"hidden": true` and never rendered — the
scene row owns it. When nothing is visible, the strip says so instead of
collapsing to an empty bar.

## Validation

- `node --check` on every changed file.
- Assemble the exact fragment source the runner builds and type-check all 11
  shaders with glslang (`#version 300 es` mechanically rewritten to Vulkan
  semantics; the shader body is passed through untouched).
- Feed checks over `shader × scene × time`: every value finite; every cage
  sphere satisfies `abs(center[axis]) + radius <= cageSize`; every top ball
  reaches contact at exactly `cageSize + radius` and never leaves the top square.
- Drive the real `index.html` in jsdom with a mocked WebGL2 context and assert:
  - the scene survives every scene-aware shader switch, and the shader survives
    every scene switch;
  - `uScene` reaches the metadata with the right value for each scene;
  - picking a Shadertoy original moves the scene to `own` and says so;
  - picking a shared scene from an original moves the shader to that scene's
    native renderer and says so;
  - the `own` button is disabled for scene-aware shaders;
  - cage sliders appear only in the cage scene, `spread` only outside it, and
    the old per-shader `scene` dropdown is gone;
  - all 11 shaders × all 5 scenes select without an error.
- Browser: check that the cage scene still reads correctly in
  `analytic_layers`, and that `analytic_layers` in `checker`/`rainbow`/
  `colorbox` shows 61 drifting spheres with no wire cube and no top balls.

## Out of scope

- Teaching the Shadertoy originals and the cubemap variants the shared scenes.
- New scenes or new bubble shaders.
- The benchmark panel (it builds its own metas and never used the scene row).
