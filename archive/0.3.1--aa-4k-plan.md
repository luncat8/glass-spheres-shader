# Plan — 4K benchmark resolution + SMAA 1x AA in live viewport

Saved at `.kilo/plans/1788600547140-aa-4k-plan.md`.

## Goal

1. Add a 4K (3840×2160) tier to the benchmark's `RES` ladder.
2. Add SMAA 1x anti-aliasing as a post-process pass over the live canvas for resolutions ≤ 2560×1440.
3. Add a toolbar `aa: on/off` toggle.
4. Benchmark stays AA-free. (User answered "live viewport only" when asked explicitly; the user message "for resolutions up to 2k in viewport and benchmark" was clarified by that answer.)

## Constraints (from AGENTS.md + code)

- Classic `<script>` tags, no modules, no build, file:// friendly.
- WebGL2 only, zero deps, no internet links → vendor SMAA 1x as `js/smaa.js`.
- No allocations in the per-frame path. Allocate once at init.
- Single tab indentation, LF endings.

## Data flow

Live view, AA on:

```
fragment shader ──▶ sceneFBO (RGBA8, full size, LINEAR filter)
                  ──▶ SMAA edge-detect   → edgesTex      (R8,  half size)
                  ──▶ SMAA blending wt.  → blendTex      (RGBA8, half size)
                  ──▶ SMAA neighborhood  → default FB
```

Live view, AA off (or canvas > 2560×1440): scene draws direct to default framebuffer. **No FBO.** Zero per-frame AA cost.

Benchmark: unchanged — draws direct to its own canvas, no FBO, no SMAA.

## Files

### Add `js/smaa.js` (new)

Self-contained. Defines `window.SMAA = { init(gl), run(gl, srcTex, w, h) }`.

Init does, once:
- Compile three fragment programs (edge / blend weight / neighborhood) plus a shared fullscreen-tri vertex shader (reuse the same `gl_VertexID` trick as `runner.js`).
- Allocate `edgesTex` (R8, half size), `blendTex` (RGBA8, half size), plus a small framebuffer for each. Use `R8` / `RGBA8` internal formats with `gl.LINEAR` on edge tex, `gl.LINEAR` on blend tex.
- Pre-decode and upload SMAA's two LUTs (`areaTex` 160×560 RGBA8, `searchTex` 64×16 R8) from inlined byte arrays. No per-frame alloc, no string concat in the hot path.
- One VAO for the fullscreen triangle, shared across all three passes.
- On compile/link failure, throw — let `runner.js` decide what to do.

`run(gl, srcTex, w, h)` does, each frame:
- 3 `drawArrays(gl.TRIANGLES, 0, 3)` calls, 3 program binds, 3 viewport changes. No allocations, no closures.

License: SMAA is MIT, https://github.com/iryoku/smaa. Keep the MIT header in `smaa.js`.

### Edit `js/runner.js`

- Add to `Runner`:
  - `aa: true` — current state.
  - `smaa: null` — set by `init` if SMAA loads.
  - `smaaMaxW: 2560`, `smaaMaxH: 1440` — gate.
  - `sceneFBO: null`, `sceneTex: null`, `sceneW: 0`, `sceneH: 0` — only used when AA is on.
- In `init(canvas)` after `Runner.gl = gl`:
  - `if (root.SMAA) { try { Runner.smaa = root.SMAA.init(gl); } catch (e) { Runner.smaa = null; Runner.aa = false; } }`
  - If `Runner.smaa` is null but `aa` was true, set `aa = false` and log once to the existing error surface.
- New helper `ensureSceneFBO(w, h)`:
  - If `Runner.sceneW === w && Runner.sceneH === h`, return.
  - Else delete old FBO + tex, create new RGBA8 texture sized w×h with `gl.LINEAR` filter and `gl.CLAMP_TO_EDGE` wrap, attach to a new FBO, store. Set `sceneW/sceneH`.
- In `frame()`:
  - After `gl.drawArrays(gl.TRIANGLES, 0, 3)`:
  - If `Runner.aa && Runner.smaa && w <= Runner.smaaMaxW && h <= Runner.smaaMaxH`:
    - `ensureSceneFBO(w, h)`, `gl.bindFramebuffer(gl.FRAMEBUFFER, Runner.sceneFBO)`, re-issue the user-shader draw, then `Runner.smaa.run(gl, Runner.sceneTex, w, h)`, then `gl.bindFramebuffer(gl.FRAMEBUFFER, null)`.
    - **Important:** the simplest way to avoid "draw twice" is to move the `drawArrays` call *into* a helper `drawScene()` and call it either direct to default FB or to the scene FBO depending on `aa`. This keeps the hot path allocation-free (the helper is one closure-free function).
  - Else: draw direct to default FB (current behavior). No FBO created.
- Expose on `api`: `setAA(on)`, `getAA()`. `setAA` updates `Runner.aa` and the toolbar button label via a callback registered by `ui.js` (or by passing the button to `init` — pick the callback approach, matches `Cam.onModeChange`).
- Keep the `IS_NODE` branch untouched so `tools_GPU/check-glsl.mjs` keeps working.

## Risks and mitigations

- **Hot-path allocation from `drawScene` helper.** Make it a top-level `function drawScene()` (not a closure), called either with the default FB or the scene FBO bound. No `{}/[]` inside.
- **FBO color filter.** Default for FBO color attachments is `NEAREST`. SMAA needs `LINEAR` on `sceneTex` and `blendTex`. Set explicitly in `ensureSceneFBO` and SMAA init.
- **Resize churn.** `ensureSceneFBO` only reallocates when `w`/`h` change. DPR ≤ 2, so two resolutions to handle per device. Cheap.
- **4K memory.** 3840×2160 RGBA8 ≈ 33 MB on the bench canvas. Single short-lived alloc per run, no leak. Accept.
- **SMAA on weak GPUs at 1440p.** Mitigated by 2K gate + toolbar toggle.
- **Benchmark scores unchanged** (AA off) — keeps the existing ranking meaningful.
- **`preserveDrawingBuffer: true` on the live context** is unused (no `toDataURL`/`drawImage` paths) but harmless. Leave it.
- **Pointer/touch handling** reads `canvas.width/height` for the click pixel position; still correct since the canvas size is unchanged.

## Validation

1. Open `index.html` in a browser. Toolbar shows `aa: on` next to `cam`. Toggling flips the label and visibly softens thin-film ring silhouettes.
2. Resize the window past 2560 wide. AA button stays "on" in UI but no SMAA pass runs (verifiable by FPS being equal to AA-off FPS at the same resolution).
3. Run the benchmark. `render` dropdown lists `320 × 180`, `640 × 360`, `1024 × 576`, `2560 × 1440`, `3840 × 2160`. Auto-mode can pick 4K when calib is < 2.5 ms.
4. Verify FBO leak: run the benchmark once, check `gl.getError()` after a run = 0, and `gl.createFramebuffer` count after 5 resizes of the live canvas is constant.
5. `node tools_GPU/check-glsl.mjs` still passes (the `IS_NODE` branch in `runner.js` is unchanged).
