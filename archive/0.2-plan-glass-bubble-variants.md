## Goal

Three renderers of the same 4-bubble scene, switchable in-browser, so the look/cost
tradeoff can be judged by eye:

| id | technique | what it buys | cost |
|---|---|---|---|
| `thick_analytic` | 4 analytic ray-sphere pairs, Beer-Lambert over the chord, Fresnel rim, **true back-to-front composite** | correct overlap order; cheapest | ~4 quadratics/px |
| `thick_raymarch` | smin-merged SDF of 4 spheres, refract-in → march inside (negated SDF) → refract-out, 2 reflection bounces | soap-blob merging where bubbles touch, real second-surface refraction | ~3 marches/px |
| `thick_chain` | as above + the exiting ray is re-injected as a primary ray, 3 hops | see-through *stacks* of bubbles (glass behind glass) | ~6 marches/px |

All three are **solid** glass (the "wall" is the chord). That is the deliberate v0.2
simplification; it looks like a marble, not a bubble.

## Shared spec (all three)

* Camera: `iMouse.x` orbit, 60° FOV, eye at `-fw*5`, identical to `XdXXzB` — `GLSL.camera`.
* Scene: 4 animated spheres, same formula as `thick_glass.js` — `GLSL.bubbles4`.
* Channels: `{"0":"env_cube","1":"env_cube","2":"noise","3":"noise"}`; `iChannel0/1` are
  `samplerCube` (runner's `resolveChannelKinds` honours the `env_cube` hint).
* Per-bubble absorption (Beer-Lambert, distinct hues so overlap is readable):
  amber `(0.35,0.20,0.10)`, cobalt `(0.10,0.30,0.45)`, rose `(0.40,0.10,0.25)`, emerald `(0.15,0.40,0.15)`.
* `IOR 1.55`, Schlick `F0 = 0.04`, plus a cheap specular sun so the spheres read as solid.

## A — `shaders/thick_analytic.js`

```
per bubble i in 0..3:
    (tE,tX) = ray_sphere(ro,rd,c_i,r_i);      valid = tX > 0
    n  = normal at tE                          (if tE<0 → camera inside, use tX/back normal)
    F  = schlick(dot(-rd,n))
    rd_in = refract(rd,n,1/IOR)                (TIR → reflect)
    chord = tX-tE ; T = exp(-absorb_i*chord)
    through = env(rd_in) * T                   + inner back-wall highlight
    col_i = mix(through, env(reflect(rd,n)) + sun, F)
    a_i   = clamp(F + (1-F)*(1-mean(T)) + rim, 0, 1)
sort the four (t,col,a) records back-to-front with a 5-comparator network
composite: col = mix(col, L.col, L.a) for L in back..front
```

The sorting network `(0,1)(2,3)(0,2)(1,3)(1,2)` on `struct Layer { float t; vec3 c; float a; }`
is branch-cheap, allocation-free and needs no indexing. Misses get `a = 0`.

## B — `shaders/thick_raymarch.js`

`map(p)` = `opSmoothUnion` over the 4 spheres (k = 0.35) and returns `vec2(d, matId)`
where the material id is the argmin of the un-smoothed distances (so the tint blends where
bubbles merge). `march(ro,rd,side)` steps `side*d` (side = -1 marches the inside).

`shadeHit()` does refract-in / march-inside / refract-out, tints by `exp(-absorb*chordInside)`,
adds `roughness`-scaled reflection, and returns the next reflection ray through `inout` params.
`mainImage` calls it once + 2 bounces with an accumulating reflection filter.

## C — `shaders/thick_chain.js`

Same SDF. Loop `hop = 0..2`:
miss → add `throughput * env(rd)` and break;
hit → add `throughput * F * (env(reflect) + sun)`, refract in, march inside, refract out,
`throughput *= (1-F) * exp(-absorb*chordInside)`, restart from the exit point.
Break early when `throughput` drops below 0.02. Tail: `throughput * env(rd)`.

## Validation (all offline, no GPU)

1. `node --check` on each new file.
2. `node tools_GPU/check-glsl.mjs` — loads `js/glsl_lib.js` + every `shaders/*.js` in a fake
   `window`, rebuilds the exact fragment source the runner would (`buildFSHeader` + source +
   footer, cube/2D sampler flags included) and runs **`glslangValidator`** on it as ESSL 3.00.
   Any compile error fails the run.
3. Manual look in the live preview (real GPU in the user's browser), FPS readout in the bar.

`js/runner.js` needed one tiny change to make (2) possible: under node it now exports
`buildFSHeader / resolveChannelKinds / FS_FOOTER` instead of an empty stub. Browser behaviour
is byte-identical.
