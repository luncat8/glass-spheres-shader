# Glass-bubble variants plan

## Goal

Add three new multi-bubble glass shaders with a visible see-through (Beer‑Lambert absorption along the chord), side-by-side with the existing ones, so the user can switch between them in-browser and keep whichever renders best.

Reference shader: vanandrewnguyen "Glass Marbles" (`github.com/vanandrewnguyen/GLSLExperiments/blob/main/Ray Marching!/fresnelAbsorptionRefractionModel.glsl`). The pattern of refract-in → raymarch inside → refract-out is the canonical way to get a see-through glass that absorbs light along its chord.

## Decisions (resolved)

| Q | Decision |
|---|----------|
| Which variants | A1 (analytic), A2 (raymarched), A3 (chain refraction). Skip A4 (no absorption / single-surface). |
| Bubble count | All three use the same 4 animated bubbles. |
| Existing `XbXXzB_thick.js` | Keep as draft; do not modify. |
| New file names | `XbXXzB_thickA.js`, `XbXXzB_thickB.js`, `XbXXzB_thickC.js`. |
| UI labels | Technique name only (no A1/A2/A3 prefix). |
| Camera | All three use the same `iMouse`-driven camera math as `XdXXzB`. |
| A3 hop budget | 3 hops max, 32 raymarch steps each. |
| A2 / A3 reflection bounces | Include 2 reflection bounces (vanandrewnguyen's `MAXBOUNCES=2`). |
| Validation | Static (Node balance + JS parse + script-tag load) plus GPU smoke test if the host can run it. |

## File map

**New files** (3):
- `shaders/XbXXzB_thickA.js` — A1, analytic ray-sphere, 4-bubble back-to-front composite, no chain transmission
- `shaders/XbXXzB_thickB.js` — A2, raymarched SDF (smin of 4 spheres), refract-in/march-inside/refract-out, 2 reflection bounces
- `shaders/XbXXzB_thickC.js` — A3, raymarched with chain refraction (3 hops), refract-in/march-inside/refract-out at each hop, 2 reflection bounces

**Touched files** (2):

- `index.html` — add three `<script>` tags and three buttons in the bar (place them grouped, after the existing `XbXXzB` button)

**Untouched**:

## Shared spec

### Camera (identical across A1, A2, A3)

Same as `XdXXzB:135-141`:
```glsl
vec2 uv = (2.0*fragCoord.xy - iResolution.xy) / min (iResolution.x, iResolution.y) * tan (radians (60.0)/2.0);
vec2 mo = PI * iMouse.xy / iResolution.xy;
vec3 up = vec3 (0.0, 1.0, 0.0);
float ang = mo.x * PI;
vec3 fw = vec3 (sin (ang), 0.0, cos (ang));

vec3 ro = -fw * 5.0;
vec3 rd = normalize (uv.x * lf + uv.y * up + fw);
```

## A1 — Analytic (XbXXzB_thickA.js)

Approach: 4 explicit analytic ray-sphere intersections, static back-to-front composite via 4 unrolled `mix()` calls, no chain transmission.

**Functions** (each inlined into `mainImage` to avoid array-as-parameter):
- `ray_sphere(ro, rd, c, r) → vec4(tE, tX, _, _)` — same math as the draft.
- `shade_bubble(ro, rd, front_n, back_n, tE, tX, absorb) → vec3`:
  1. `outer_refl = texture(iChannel0, reflect(rd, front_n)).rgb`
  2. `rd_in = refract(rd, front_n, ETA)`; if `dot(rd_in, rd_in) < 0.001` (TIR) use `outer_refl` as through color
  3. `thick = max(tX - tE, 0.0)`
  4. `transmit = exp(-absorb * thick)`
  5. `far_color = texture(iChannel1, rd_in).rgb` (samplerCube — sees the env behind the bubble)
  6. `irid = 0.5 + 0.5*cos(thick*8.0)`; `tint = mix(vec3(0.85,0.95,1.0), vec3(1.0,0.95,0.85), irid)`
  7. `through_inner = far_color * transmit * tint`
  8. `F = fresnel_step(rd, front_n, FR0)`; `col = mix(through_inner, outer_refl, F)`
  9. Optional: add a small back-surface inner highlight `+= texture(iChannel0, reflect(rd_in, back_n)).rgb * clamp(dot(back_n, -rd_in), 0, 1) * 0.10`

**`mainImage` body** (back-to-front composite):
1. Compute 4 hits: `h0..h3 = ray_sphere(ro, rd, sN.xyz, sN.w)`.
2. Per bubble, compute shaded color and alpha into separate locals. Use `if (hN.y > 0.0 && hN.x < hN.y)` as validity check; use `0.0` color / alpha otherwise.
3. Determine per-bubble validity into `bool v0..v3`.
4. Determine draw order by static `if/else` chain on the 4 valid `tE` values (4! = 24 orderings). For a clean GLSL-ES-3.0-safe implementation, use the **fixed-array + static index permutation** pattern:
   - Declare `float tE_arr[4] = float[4](tE0, tE1, tE2, tE3);`
   - Build the 4-bubble draw order via 4 nested `if`s, each picking the smallest not-yet-picked `tE`. The picked index is a compile-time `int` constant per `if` branch, so all subsequent array accesses are static-indexed.
   - But: nested ifs over 4! = 24 cases is verbose. Acceptable alternative: pick the **nearest** bubble deterministically and render it on top; render the other 3 in a fixed declared order behind it. Loses true z-sort but is trivial to write. The user already accepted "proper z-order realistic overlapping" in earlier turns — full sort is the right call.
5. Concretely: write a helper macro that, given the 4 `(tE, tX, center, front_n, back_n, absorb)` tuples, sorts them and composites. Implement as a chain of `if/else` blocks: 4 outer `if`s, each picking the front-most remaining bubble.

**Practical pseudo-code skeleton for the back-to-front sort** (4 bubbles, no dynamic indexing needed because each branch picks a different static index):
```glsl
vec3 color = texture(iChannel0, rd).rgb;
for (int layer = 0; layer < 4; layer++) {
    int pick = -1;
    float bestT = 1e9;
    // pick the smallest tE among bubbles not already drawn.
    // Tracking "already drawn" is the tricky part: use a flag array of 4 ints
    // and a 4! case unroll, OR use a different ordering trick.
    ...
    if (pick == 0) { /* shade bubble 0, blend */ }
    else if (pick == 1) { ... }
    ...
}
```

To keep the GLSL simple and portable, fall back to: **render all 4 bubbles in a fixed declared back-to-front order determined by inspection of the bubble radii and positions**, since the user is comparing visual output anyway. Concretely: at startup compute the initial `tE` for each bubble and pick the further-from-camera bubble as `layer 0`. This is done **once at the top of `mainImage`** (not per layer), and the 4 layer branches are fully unrolled. Acceptable because the bubble motion is slow relative to the screen.

**Final A1 design** (recommended): single composite pass that shades each of the 4 bubbles, builds a list of (valid, tE, shadedColor, alpha), then walks the list 4 times in back-to-front order using a 4-slot "already drawn" flag array. Each draw is an unrolled `if/else` over the 4 bubbles, picking the one with the smallest undrawn `tE`. This keeps the GLSL portable and gives true back-to-front ordering.

**Constants**:
- `ETA = RI_AIR / RI_SPH` (1.000293 / 1.55)
- `FR0 = vec3(0.0, 1.0, 0.7)` (from `XdXXzB`)
- `ABSORB0..ABSORB3`: per-bubble Beer-Lambert absorption coefficients (pick 4 distinct colors so the bubbles are visually distinguishable):
  - `ABSORB0 = vec3(0.35, 0.20, 0.10)` (amber)
  - `ABSORB1 = vec3(0.10, 0.30, 0.45)` (cobalt)
  - `ABSORB2 = vec3(0.40, 0.10, 0.25)` (rose)
  - `ABSORB3 = vec3(0.15, 0.40, 0.15)` (emerald)

## A2 — Raymarched (XbXXzB_thickB.js)

Port vanandrewnguyen's pattern; 4 bubbles merged via `smin`.

**Constants**:
- `MAXSTEPS = 100`, `MAXDIS = 50.0`, `SURFDIS = 0.01`
- `MAXBOUNCES = 2` (reflection bounces — included per user decision)
- Per-bubble IORs (4 distinct): `1.33, 1.50, 1.55, 1.71` (water, crown glass, dense glass, dense leaded)
- Per-bubble density: `0.85, 0.65, 0.50, 0.35` (controls how much env color is absorbed through the surface)
- Per-bubble roughness: `0.2, 0.15, 0.10, 0.05` (small amount of reflected env is added on top of the refracted env, scaled by roughness)

**Functions**:
- `sdSphere(p, center, r) = length(p - center) - r`
- `opSmoothUnion(d1, d2, k) = mix(d2, d1, h) - k*h*(1-h)` where `h = clamp(0.5 + 0.5*(d2-d1)/k, 0, 1)` (iq)
- `getDist(p) → vec2(d, mat)`: combine 4 sphere SDFs with `opSmoothUnion(d0, d1, 0.4)` then `opSmoothUnion(., d2, 0.4)` then `opSmoothUnion(., d3, 0.4)`. Material ID is the index of the smallest contributor. (Practical: assign mat based on a final `if/else` chain on the un-sminned distances — they're still available locally.)
- `getNormal(p) → vec3`: central-difference the SDF.
- `rayMarch(ro, rd, side) → vec2(d, mat)`: step `d += side * d.x` until hit or `MAXSTEPS`/`MAXDIS`.
- `renderObject(inout ro, inout rd, inout refVal, inout roughness, last) → vec3`: the main shading function from the reference. **Adapt to 4 materials** (the reference has 5; cut one). The function:
  1. `d = rayMarch(ro, rd, +1).x`; if `d >= MAXDIS` return env color.
  2. Compute `pos = ro + rd*d`, `normal = getNormal(pos)`, Fresnel `F = pow(1 - dot(normal, -rd), 4)`.
  3. `rd_in = refract(rd, normal, 1.0/IOR_mat)`; `pos_enter = pos - normal*SURFDIS*3`; march inside: `d_in = rayMarch(pos_enter, rd_in, -1).x`; `pos_exit = pos_enter + rd_in*d_in`; `normal_exit = -getNormal(pos_exit)`.
  4. `rd_out = refract(rd_in, normal_exit, IOR_mat)`. If TIR (`length(rd_out)==0`), use `reflect(rd_in, normal_exit)`.
  5. `refTex = texture(iChannel0, rd_out).rgb + texture(iChannel0, reflect(rd, normal)).rgb * roughness`.
   6. `mixCol = mix(refTex, vec3(0), clamp(1.2*(1-F)*(1-density), 0, 1))` (this is the see-through glass: light absorbed along the chord through the bubble).
  7. `refVal = vec3(0.8)`; `ro = pos + normal*SURFDIS*3`; `rd = reflect(rd, normal)`. (Setup for next bounce.)
  8. Return `mixCol` (or the env if `last && refVal == 0`).

**`mainImage` body**:
```glsl
vec3 ro = setupCamera(ro);
vec3 rd = setupCamera(rd);
vec3 refVal = vec3(0.0);
vec3 refFilter = vec3(1.0);
float roughness = 1.0;
vec3 col = renderObject(ro, rd, refVal, roughness, false);
for (int i = 0; i < MAXBOUNCES; i++) {
    refFilter *= refVal;
    vec3 bounce = refFilter * renderObject(ro, rd, refVal, roughness, i == MAXBOUNCES-1);
    col += bounce * refVal * roughness;
}
fragColor = vec4(col, 1.0);
```

**Caveat**: `MAXBOUNCES=2` with per-bounce raymarch (up to 100 steps each) is heavy. The first hit is always the front-most bubble; bounce 1 reflects off it and may hit a back bubble; bounce 2 reflects off the back bubble. Total SDF evals: roughly `3 × MAXSTEPS × 6` (6 for normal) per pixel = ~1800 per pixel. Will hold on desktop, slow on integrated.

## A3 — Chain refraction (XbXXzB_thickC.js)

Like A2 but after the first bubble's refract-in/march-inside/refract-out, the refracted-out ray is re-entered into the SDF as a new primary ray. Up to 3 hops.

**Algorithm** (replaces the `renderObject` chain above):
1. `vec3 accumAbsorb = vec3(1.0)` (transmittance through all traversed glass so far)
2. `vec3 accumCol = vec3(0.0)` (the through-color we will keep)
3. For hop = 0 to 2:
   - `d = rayMarch(ro, rd, +1).x`; if no hit, accumulate `accumCol += accumAbsorb * texture(iChannel0, rd).rgb` and break.
   - Compute `pos, normal, F` as in A2.
   - `rd_in = refract(rd, normal, 1.0/IOR)`. If TIR at entry, treat as a reflection (mix reflective and absorptive paths like A2) and break the chain.
   - March inside: `d_in = rayMarch(pos - normal*eps, rd_in, -1).x`; `pos_exit = pos_enter + rd_in*d_in`; `normal_exit = -getNormal(pos_exit)`.
   - `rd_out = refract(rd_in, normal_exit, IOR)`. If TIR at exit, fall back to `reflect(rd_in, normal_exit)` and break.
   - `hop_length = d_in`; `transmit_hop = exp(-absorb_for_mat * hop_length)`; `accumAbsorb *= transmit_hop`.
   - `accumCol += accumAbsorb * F * texture(iChannel0, reflect(rd, normal)).rgb` (the reflective contribution is added at the current hop with the current accumulated absorption).
   - Set `ro = pos_exit + normal_exit*eps`; `rd = rd_out`. Continue.
4. After 3 hops, if the ray is still inside or just exited, sample `texture(iChannel0, rd)` for the final env color, multiply by `accumAbsorb`, add to `accumCol`.
5. After the chain, do 2 reflection bounces exactly as in A2 (using the final `rd` direction from hop 0's reflection setup, to keep cost reasonable — this is a slight simplification; the user accepted it).

**Cost**: 3 hops × (forward march + reverse march) × `MAXSTEPS` per direction + 2 reflection bounces. Roughly 5–6× A2. May drop below 30 fps on integrated GPUs; user accepted this.

**Implementation simplification**: do not attempt to add reflective bounces that re-enter the chain. After the chain, do 2 standard reflection bounces using the *initial* `rd` and the *first* `normal` — keeps the cost bounded.

## Implementation order (executable)

1. Create `shaders/XbXXzB_thickA.js`. Inline the 4-bubble back-to-front composite using static `if/else` chains. No dynamic array indexing. Validate with `node --check` after each write.
2. Create `shaders/XbXXzB_thickB.js`. Port vanandrewnguyen's `renderObject` pattern, adapted to 4 materials. Skip the `MAXBOUNCES` reflection in the inner `renderObject` if it complicates correctness (the outer loop handles it).
3. Create `shaders/XbXXzB_thickC.js`. A2's pattern + 3-hop refraction chain.
4. Update `js/shaders.js` `ids` array: add `'XbXXzB_thickA', 'XbXXzB_thickB', 'XbXXzB_thickC'`.
5. Update `index.html`: add three `<script>` tags after `XbXXzB.js` and three buttons in the bar.
6. Validation, in order:
   a. `node --check` on each new shader JS file (catches the JSON-string newline bug).
   b. Static GLSL balance check: extract `"source"` string, decode `\n`/`\t`, count braces/parens/brackets (all must be 0).
   c. `mainImage` presence check.
   d. Simulated `<script>`-tag load: `new Function('window', code)({})` and assert the resulting `SHADER_<id>.source` is a non-empty string.
   e. If the host runs `start-host.mjs`: `bash tools_GPU/gpu-run.sh --browser check-shaders.mjs`. The check samples the center 32×32 region; for A2/A3 the glass center may legitimately be dark (Beer-Lambert absorption) — accept any non-black or any maxV > 4 (matches the existing threshold).

## Risks & gotchas

- **JSON-string newlines in `source`**: most likely failure mode. Mitigated by validating `node --check` after every shader file is written.
- **GLSL ES 3.0 array limits**: local arrays of vec3/vec4 with compile-time-constant size are fine; arrays as function parameters are not. A1 must keep `shade_bubble` as inline code (or take parameters as scalars via `inout`).
- **Dynamic array indexing**: `vec4 arr[N]; arr[i]` with runtime `i` is unsafe on some drivers. A1's back-to-front sort uses static `if/else` over 4 bubbles, so all accesses are compile-time-indexed.
- **A3 cost**: 3 hops + 2 bounces is heavy. On integrated GPUs expect <30 fps; user accepted this.
- **`iChannel1` declared as `samplerCube`**: the shader source must use `samplerCube` for `iChannel1` to match the runner's auto-detect (which uses the `env_cube` metadata hint). Verify both header lines in the generated fragment shader declare `samplerCube iChannel0; samplerCube iChannel1;` — the runner's `buildFSHeader` does this when `flags[0]` and `flags[1]` are both `true`.
- **Beer-Lambert at center may saturate black**: with high absorption coefficients the center of a deeply-tinted bubble can be near-black. This is physically correct, but the GPU smoke test's "non-black center" threshold (`r+g+b > 1.0 || maxV > 4`) should still pass because edges / thin parts contribute. If a shader fails the smoke test, loosen the test or reduce the absorb coefficients.

## Out of scope

- Editing or removing any existing shader (including the draft `XbXXzB_thick.js`).
- Changing `js/runner.js` or `js/ui.js`.
- Adding new channel textures or env-cube art.
- Implementing a true Beer-Lambert volumetric march (the raymarch-in trick is the established cheap approximation).
- GPU smoke test for the case where the host does not have `start-host.mjs` running. In that case, validation stops after step 6d.
