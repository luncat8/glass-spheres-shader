# Plan 0.4.3 — shape selector: what the objects are

From `0.4.3-object-shape-mesh-draft.md`: buttons that turn every object
(currently always a sphere) into a **sphere**, a **cube**, a **tetrahedron** or a
**knot** (the classic 3D demo object). Shaders that cannot express a shape — or
where it is disproportionately hard — are skipped, exactly like the scene
selector skips the Shadertoy originals.

## Model — a third orthogonal selector

The toolbar gains a third axis, same rules as the other two (AGENTS.md
"concepts"):

| selector | question | values |
|---|---|---|
| **shader** | *how* the objects are drawn | one entry per `shaders/*.js` |
| **scene** | *where* they are drawn and *how* they move | own, checker, rainbow, color box, cage, (terrain — plan 0.4.4) |
| **shape** | *what* they are | sphere, cube, tetra, knot |

Shape is global (`curShape` in `js/ui.js`), survives a shader switch and a scene
switch, and is written into a hidden int param `uShape` on the selected shader
(0 = sphere, 1 = cube, 2 = tetra, 3 = knot) — the same mechanism `uScene` uses.

A shader declares what it can render:

```js
window.SHADER_x = { id: 'x', shapes: ['sphere','cube','tetra'], nativeShape: 'sphere', ... }
```

Fallback rule is unchanged from scenes: **the selector the user clicked wins**,
the other one falls back to its native partner, and the toolbar says so.

```text
picked a shape the current shader cannot draw -> shader := nativeShader(shape)
picked a shader that cannot draw current shape -> shape  := nativeShape(shader)
```

`native` per shape: `knot` → `thick_raymarch` (the cheapest renderer that can
march it), everything else → `analytic_layers` (the most capable analytic one).
A shape a shader does not list gets an `alt` (dashed) button; a shape no
registered shader can draw gets a disabled one — never a silently ignored click.

## No mesh assets

The draft says "object mesh **or** analytic formula". Meshes are out: the runtime
is `file://` friendly, zero-dependency, no fetch and no build, and every renderer
here is a fragment-shader ray tracer with no vertex pipeline to feed. So all four
shapes are **analytic formulas**, which also keeps them resolution-independent,
perfectly smooth and free of asset loading:

| shape | signed distance | ray intersection | convex |
|---|---|---|---|
| sphere | `length(p) - r` | closed form (existing `ray_sphere`) | yes |
| cube | `max(abs(p)) - a` | 3-axis slab clip | yes |
| tetra | `max(dot(-vᵢ, p)) - a/3` | 4-plane convex clip | yes |
| knot | (2,3) torus knot, iq-style curve distance | bounded sphere-trace only | **no** |

The cube and the regular tetrahedron are both *exact* SDFs of the form
`max(plane distances) - inradius`, so one convex-polytope intersection routine
serves both: clip the ray against the shape's face planes and keep
`[t_enter, t_exit]`, which also yields the entry and exit face normals for free.
The knot has no cheap closed-form intersection, so it exists only where a
marcher already exists.

### One bounding ball, one size slider

Every shape is **inscribed in the object's bounding ball of radius `w`** — the
`w` the feeds already write:

```js
// js/shapes.js, and the GLSL block is generated from the same table
const INSCRIBE = { sphere: 1.0, cube: 1 / Math.sqrt(3), tetra: 1.0, knot: 1.0 };
```

so a cube's half-edge is `w/√3` and a tetra's circumradius is `w`. That single
decision is what makes the change cheap everywhere else:

* feeds, `uSize`, `uSpread`, cloud spacing and the cage bounds keep their
  meaning — nothing is resized;
* the camera's orbit target, `Cam.sel` and the selection halo keep working on the
  bounding ball;
* objects never overlap more than they already do, so no renderer has to cope
  with a new density regime.

## Orientation

A cube or tetrahedron that never turns looks dead, so each object carries a
spin. It is **data, not GLSL math**: the same axis/angle must be known to the
renderer (to intersect) and to `js/camera.js` (to pick), and a formula
duplicated in two languages drifts silently.

```js
// js/scene.js
Feeds.spin = function (time, meta, out) {
	// out[i] = (axis.xyz normalised, angle in radians)
	// axis and speed are golden-angle spread over the index, so no two objects
	// share an orientation or a rate; angle = time * speed + phase
};
```

Shaders that support shapes declare one more array:

```js
"arrays": [
	{ "name": "uBubbles", "type": "vec4", "count": 32, "feed": "bubbles" },
	{ "name": "uSpin",    "type": "vec4", "count": 32, "feed": "spin"    }
]
```

The feed writes the angle already advanced by `time`, so GLSL never touches the
clock for orientation and JS can read the very same buffer when it picks. In the
cage scene the spin is frozen to its phase (see "Cage contact" below).

`multi_thinfilm` computes its own centres in GLSL (`bubblePos (i, iTime)`) and
has no picking at all, but it still declares the `uSpin` array: one orientation
mechanism across the project, and no GLSL-side clock that a future pick or a
future shared-camera migration would have to mirror.

## Shared GLSL — `GLSL.shape`

New block in `js/glsl_lib.js`, interpolated by every supporting shader next to
`GLSL.raySphere`. It is deliberately **self-contained** — no `PI`, `saturate1` or
`BIG` from `GLSL.common`, literals where a constant is needed — because
`multi_thinfilm` (and later `multi_fresnel` / `thick_glass`) are self-authored
shaders that predate `glsl_lib.js` and would otherwise have to be migrated onto
`GLSL.common` just to draw a cube:

```glsl
// one entry point per family, both driven by uShape and the object's spin
mat3 spinMat (vec4 s);                                    // Rodrigues from (axis, angle)
vec4 spinObj (vec4 obj, vec4 s);                          // convenience: none for spheres

// analytic family: exact enter/exit + outward normals (sphere, cube, tetra)
vec2 shapeHit (vec3 ro, vec3 rd, vec4 obj, vec4 spin, out vec3 nEnter, out vec3 nExit);

// marcher family: signed distance in the object's local frame
float shapeSdf (vec3 p, vec4 obj, vec4 spin);

// shared convex-polytope core used by both cube and tetra
vec2 convexHit (vec3 ro, vec3 rd, vec4 obj, mat3 rot, int faces, out vec3 nEnter, out vec3 nExit);
```

`shapeHit` is a drop-in replacement for `ray_sphere` with the same
`vec2(t_enter, t_exit)` / `y < x` = miss contract, so the analytic shaders change
one call site plus their normal computation. `shapeSdf` replaces
`length(p - c) - r` inside the existing `smin` merges, which keep working for
every shape (soap-film merged cubes and knots are a feature, not a problem).

The numeric constants (inscribe factors, tetra vertices, knot winding and tube
radius) live **once**, as a JS table in `glsl_lib.js`; the GLSL `#define`s are
generated from it and `js/shapes.js` reads the same table for picking, so the two
languages cannot disagree.

## Capability matrix

| shader | geometry core | sphere | cube | tetra | knot |
|---|---|:-:|:-:|:-:|:-:|
| `analytic_layers` | analytic, nearest-3 layers, ≤61 objects | ✓ | ✓ | ✓ | — |
| `hollow_bubbles` | analytic membrane, outer + inner shell, ≤32 | ✓ | ✓ | ✓ | — |
| `thick_analytic` | analytic chord, depth sorted, 4 | ✓ | ✓ | ✓ | — |
| `thick_raymarch` | scene SDF, `smin`, 4 | ✓ | ✓ | ✓ | ✓ |
| `thick_chain` | scene SDF, `smin`, 3 hops, 4 | ✓ | ✓ | ✓ | ✓ |
| `multi_thinfilm` | scene SDF, `smin`, 6λ, 3 | ✓ | ✓ | ✓ | ✓ |
| `multi_fresnel` | analytic, own camera, 4 | — | — | — | — |
| `thick_glass` | analytic, own camera, 4 | — | — | — | — |
| `XdXXzB`, `ld3SDl`, `llsSDf` | Shadertoy originals | — | — | — | — |
| `bench_*` | benchmark entries | — | — | — | — |

Why the gaps:

* **knot in the analytic renderers — skipped.** Those shaders promise
  constant-bound, march-free work per pixel. A knot needs ~30 sphere-trace steps
  *per object*, i.e. ~1800 steps for `analytic_layers` at 61 objects. That is a
  different renderer, not a variant. The knot is therefore SDF-shader-only, and
  picking a knot while an analytic shader is active switches the shader to
  `thick_raymarch` (with the usual note).
* **`multi_fresnel` / `thick_glass` — phase 2.** Their analytic cores are
  sphere/cube/tetra capable, but they derive surface normals inline as
  `normalize (p - center)` at every shading branch (`pn0`/`pn1`,
  `front_n`/`back_n`), so adopting `shapeHit`'s enter/exit normal contract means
  rewriting each of those branches, and neither has a shared camera to validate
  picking against. Mechanical but wide — they keep `shapes: ['sphere']` until it
  is done.
* **originals — never.** `ld3SDl` would be easy (its warped sphere is already an
  SDF) but the ports stay byte-faithful to Shadertoy; that is their value.
* **bench — never.** The benchmark compares *techniques* on one identical scene;
  letting geometry vary would make its numbers incomparable.

## Tasks

### 1. `js/caps.js` — one capability registry for both axes (new)

`js/scenes.js` and the new shape registry need the same five operations
(`supported`, `supports`, `nativeOf`, `nativePartner`, `apply`, `paramVisible`).
Extract them, parameterised by axis, instead of copying the file:

```js
Caps.axis({ list, metaKey: 'scenes', paramName: 'uScene', nativeKey: 'nativeScene' })
```

`js/scenes.js` keeps its public API (`Scenes.list/get/supports/...`) and becomes
a thin binding over `Caps`; `js/shapes.js` is the same for shapes. The registry
entries carry `id`, `label`, `value` (the int written to `uShape`), `native`
(partner shader) and `hint`.

### 2. `js/shapes.js` — the shape registry (new)

Four entries (`sphere`, `cube`, `tetra`, `knot`) plus the inscribe table read
from `glsl_lib.js`, and the picking geometry:

```js
Shapes.hit(rayOrigin, rayDir, obj, spin, shapeId) -> tEnter | -1
```

* sphere — the existing closed form;
* cube / tetra — the same convex clip as GLSL, in JS, from the same constants;
* knot — the bounding ball, documented as an approximation (a knot tube sweeps
  most of its bounding ball, so the error is far smaller than a cube's would be).

### 3. `js/scene.js` — `Feeds.spin`

Per-index axis, speed and phase (golden-angle spread, matching `makeCloud`'s
style), angle already advanced by `time`. Frozen to the phase when
`uScene == 3` so the cage's closed-form bounce stays valid.

### 4. `js/camera.js` — shape-aware picking and selection

* `pickable()` also runs the `spin` feed into the matching `uSpin` buffer, and
  keeps a preallocated spin buffer next to `cagePick`;
* the hit loop calls `Shapes.hit(...)` instead of the inline ray/sphere solve;
* `Cam.sel` gains a companion `Cam.selRot` (the selected object's axis/angle),
  refreshed by `updateSelPos()` and exposed through a new `camSelRot` feed.

### 5. `js/glsl_lib.js` — `GLSL.shape`, shape-aware halo

* the constants table, `spinMat`, `convexHit`, `shapeHit`, `shapeSdf`;
* `GLSL.selGlow` uses `shapeHit` with `uSel` + the new `uSelRot` var, so the rim
  glow hugs a cube's faces instead of floating around its bounding ball;
* `analytic_layers`' local `selectionGlow` is replaced by `GLSL.selGlow` (it
  exists twice today only for historical reasons).

### 6. `shaders/*.js` — adopt the block

Per supporting shader: add `shapes` / `nativeShape`, the hidden `uShape` param,
the `uSpin` array and the `uSelRot` var, interpolate `${GLSL.shape}`, and swap
`ray_sphere(ro, rd, c, r)` → `shapeHit(ro, rd, obj, spin, nA, nB)` (or
`length(p-c)-r` → `shapeSdf(p, obj, spin)` in the marchers).

`hollow_bubbles` gets the inner surface from the same shape scaled by
`(1 - uWall)` — identical semantics to today's `Ri = R * (1 - uWall)`, so the
`wall` slider keeps meaning "fraction of the size" for every shape.

### 7. `js/ui.js` + `index.html` — the third row

`shape · what it is` row under the scene row, same `active` / `alt` / `disabled`
styling, same note mechanism, global `curShape`, `__app.setShape` / `shape` /
`shapes` / `shapeOf` browser hooks. A param may declare `shapes: [...]` to hide
itself for some shapes (`paramVisible` already generalises via `Caps`).

### 8. `AGENTS.md` + `js/prompts.js`

AGENTS.md "concepts" grows the third selector and the rule that a shader
declares `shapes: [...]` like it declares `scenes: [...]`. `prompts.js` mentions
the selected shape in the generated tech summary.

### 9. Optional, later — cage contact fidelity

Today the cage bounces on the bounding ball, so a cube visibly stops short of the
wall (its faces sit at `0.577 w`). The exact fix is cheap because the spin is
frozen in the cage scene: compute each object's rotated-AABB support per axis in
`feedCageInside` (`bound[axis] = cage - support(axis)`) and the faces touch.
Deferred because it changes the cage's look, which is its own decision.

## Validation

* **glslang type-check** of the exact fragment source the runner assembles
  (`runner.helpers.buildFSHeader` + `buildUniformDecls` + source + footer) for
  every shader × shape, as in plans 0.3.x.
* **`tools_GPU/check-shapes.mjs`** (headless, no GPU):
  * every shape's analytic JS hit agrees with a dense-sampled ground truth along
    10⁴ random rays per shape (enter/exit t within 1e-4, normal dot > 0.999);
  * `spinMat`-equivalent JS rotation keeps every vertex inside the bounding ball
    for all shapes and all angles (the inscribe claim, tested);
  * `Feeds.spin` output is finite, axis-normalised and index-stable over time;
  * `Caps` fallbacks: for every (shader, shape) pair either the pair is supported
    or exactly one partner changes, and the reported note names both.
* **`tools_GPU/check-ui.mjs`** extended: all 11 shaders × 5 scenes × 4 shapes
  select without error; unsupported combinations fall back with a note; `alt` /
  `disabled` classes match the matrix; picking still returns the right index for
  cube and tetra (a known object placed under the cursor, spin frozen).
* **Browser**: cubes and tetras tumble without intersecting more than spheres do;
  `hollow_bubbles` shows a visible wall on all three convex shapes; `smin`
  merging reads as fused glass for cube and knot in `thick_raymarch`; the halo
  hugs the shape; the knot switch moves the shader to `thick_raymarch` and says
  so.

## Out of scope

* mesh/point-cloud assets, OBJ/glTF loading, any vertex or geometry pipeline —
  everything stays a fragment-shader ray tracer;
* mixed shapes in one scene (one global shape, like one global scene);
* per-shape materials, bevels/rounding (`sdRoundBox`) and shape morphing;
* the Shadertoy originals and the benchmark entries;
* making the knot pickable exactly in JS (bounding-ball approximation instead).
