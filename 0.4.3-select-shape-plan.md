# Plan 0.4.3 — shape selector: what the objects are

From `0.4.3-object-shape-mesh-draft.md`: buttons that turn every object
(currently always a sphere) into a **sphere**, a **cube**, a **tetrahedron** or a
**knot** (the classic 3D demo object). Shaders that cannot express a shape — or
where it is disproportionately hard — are skipped, exactly like the scene
selector skips the Shadertoy originals.

## Model — a third orthogonal selector

The toolbar gains a third axis, same rules as the other two (AGENTS.md
"concepts"):

| selector | question | values |
|---|---|---|
| **shader** | *how* the objects are drawn | one entry per `shaders/*.js` |
| **scene** | *where* they are drawn and *how* they move | own, checker, rainbow, color box, cage, glass land (plan 0.4.4) |
| **shape** | *what* they are | sphere, cube, tetra, knot |

Shape is global (`curShape` in `js/ui.js`), survives a shader switch and a scene
switch, and is written into a hidden int param `uShape` on the selected shader
(0 = sphere, 1 = cube, 2 = tetra, 3 = knot) — the same mechanism `uScene` uses.

A shader declares what it can render:

```js
window.SHADER_x = { id: 'x', shapes: ['sphere','cube','tetra'], nativeShape: 'sphere', ... }
```

A shader without `shapes` supports `['sphere']` (the safe default, like `['own']`
for scenes). Fallback rule is unchanged from scenes: **the selector the user
clicked wins**, the other one falls back to its native partner, and the toolbar
says so.

```text
picked a shape the current shader cannot draw -> shader := nativeShader(shape)
picked a shader that cannot draw current shape -> shape  := nativeShape(shader)
```

`native` per shape: `knot` → `thick_raymarch` (the cheapest renderer that can
march it), everything else → `analytic_layers` (the most capable analytic one).
A shape a shader does not list gets an `alt` (dashed) button; a shape no
registered shader can draw gets a disabled one — never a silently ignored click.
Sphere is supported by every shader, so its button is never `alt`.

## No mesh assets

The draft says "object mesh **or** analytic formula". Meshes are out: the runtime
is `file://` friendly, zero-dependency, no fetch and no build, and every renderer
here is a fragment-shader ray tracer with no vertex pipeline to feed. So all four
shapes are **analytic formulas**, which also keeps them resolution-independent,
perfectly smooth and free of asset loading:

| shape | signed distance | ray intersection | convex |
|---|---|---|---|
| sphere | `length(p) - w` | closed form (existing `ray_sphere`) | yes |
| cube | exact box SDF, half-edge `w/√3` | 6 half-space clips | yes |
| tetra | `max(dot(nᵢ, p)) - w/3` (exact at faces, lower bound at edges) | 4 half-space clips | yes |
| knot | (2,3) torus knot, conservative distance estimate (below) | bounded sphere-trace only | **no** |

The cube and the regular tetrahedron are both convex polytopes, so one
half-space clip routine (`planeClip`) serves both: clip the ray span against the
face planes, keep `[t_enter, t_exit]`, and the entry and exit face normals fall
out for free. The knot has no cheap closed-form intersection, so it exists only
where a marcher already exists.

### One bounding ball, one size slider

Every shape is **inscribed in the object's bounding ball of radius `w`** — the
`w` the feeds already write:

```js
// js/glsl_lib.js SHAPE table; the GLSL #defines and js/shapes.js both read it
CUBE_INSCRIBE  = 1/√3   // half-edge of the cube whose corners touch the unit ball
TETRA_INRADIUS = 1/3    // inradius of the regular tetrahedron whose vertices touch it
KNOT_R + KNOT_A + KNOT_TUBE = 1
```

That single decision is what makes the change cheap everywhere else:

* feeds, `uSize`, `uSpread`, cloud spacing and the cage bounds keep their
  meaning — nothing is resized;
* the camera's orbit target, `Cam.sel` and the selection halo keep working on the
  bounding ball;
* objects never overlap more than they already do, so no renderer has to cope
  with a new density regime;
* every hit test starts with the ball: a ray that misses the ball misses the
  shape, so the rotation and the plane clips only run for the few objects a ray
  can actually touch.

### The knot

`(2,3)` torus knot in the object's local frame (`y` up, unit bounding ball):

```text
C(θ) = ((R + A cos 3θ) cos 2θ,  A sin 3θ,  (R + A cos 3θ) sin 2θ)
R = 0.60   A = 0.25   TUBE = 0.15      (hole radius 0.20, strand gap 0.20,
                                        minimum curvature radius 0.45 > TUBE)
```

There is no closed-form distance to the curve, so the marcher uses a
**conservative estimate** built from the meridian half-plane of the query point:
the (2,3) knot crosses every half-plane `φ` exactly twice, at the meridian points
`±A (cos 1.5φ, sin 1.5φ)`. The distance to each crossing, corrected for the
curve's local tangent (project the offset onto the plane normal to the tangent),
is an estimate of the distance to that strand; the field is
`min(strand₁, strand₂) − TUBE`. This is not Lipschitz-1 near the hole (the
half-plane spins fast close to the axis), so the marched field is

```glsl
sdKnot (p) = max (KNOT_LIP * estimate (p),  torus (p) - KNOT_HULL)
KNOT_LIP  = 0.45   // scaled step: measured min(true distance / field) = 1.03 over 2.6e5 samples
KNOT_HULL = 0.43   // the torus of meridian radius A + TUBE + 0.03 contains the whole tube exactly
```

The outer torus term is an exact distance far from the knot (so empty space is
crossed in a few big steps); inside it the scaled estimate takes over. Measured
against the estimate's own zero set: no overstep anywhere, surface error against
the true tube ≤ 0.03 in unit radius. Rejected alternatives: Newton refinement of
the seeds (surface error ≈ 0, but the estimate overshoots the distance up to
3.5× away from the surface — tunnels), and the plain two-circle fold without the
tangent correction (needs `KNOT_LIP` 0.2 for the same guarantee — twice the
steps).

## Orientation

A cube or tetrahedron that never turns looks dead, so each object carries a
spin. It is **data, not GLSL math**: the same axis/angle must be known to the
renderer (to intersect) and to `js/camera.js` (to pick), and a formula
duplicated in two languages drifts silently.

```js
// js/scene.js
Feeds.spin = function (time, meta, out) {
	// out[i] = (unit axis.xyz, angle in radians); axis, rate and phase are
	// deterministic per index (hash spread), the angle is already advanced by
	// `time`, so GLSL never touches the clock for orientation and JS reads the
	// very same buffer when it picks
};
```

Shaders that support shapes declare one more array, sized like their object
array:

```js
"arrays": [
	{ "name": "uBubbles", "type": "vec4", "count": 32, "feed": "bubbles" },
	{ "name": "uSpin",    "type": "vec4", "count": 32, "feed": "spin"    }
]
```

The spin is never frozen. The cage scene bounces every object on its bounding
ball, which is valid for any orientation; freezing would only matter for an
exact face-contact bounce (task 9, deferred), and a tumble that stops when the
scene changes reads as a bug. The `mov` toggle freezes the spin together with
the motion, since both come from the feed clock.

`multi_thinfilm` computes its own centres in GLSL (`bubblePos (i, iTime)`) and
has no picking at all, but it still declares the `uSpin` array: one orientation
mechanism across the project, and no GLSL-side clock that a future pick or a
future shared-camera migration would have to mirror.

## Shared GLSL — `GLSL.shape`

New block in `js/glsl_lib.js`, interpolated by every supporting shader right
after `GLSL.raySphere`, which it requires (it deliberately needs nothing from
`GLSL.common`: `multi_thinfilm` predates `glsl_lib.js` and only adds
`GLSL.raySphere` + `GLSL.shape` to draw a cube):

```glsl
#define SHAPE_SPHERE 0 ... SHAPE_KNOT 3           // + the constants table as #defines
mat3  spinMat  (vec4 s);                          // Rodrigues from (unit axis, angle)
void  planeClip (vec3 ro, vec3 rd, vec3 n, float d, inout vec2 t, inout vec3 nEnter, inout vec3 nExit);
vec2  boxHit   (vec3 ro, vec3 rd, vec3 c, vec3 h, out vec3 nEnter, out vec3 nExit);   // axis-aligned box (also used by GLSL.land)
float sdBox    (vec3 p, vec3 b);
float sdTetra  (vec3 p, float inradius);
float sdKnot   (vec3 p);                          // unit bounding ball, conservative

// analytic family: exact enter/exit + outward normals (sphere, cube, tetra; knot = its ball)
vec2  shapeHit (int shape, vec3 ro, vec3 rd, vec4 obj, vec4 spin, out vec3 nEnter, out vec3 nExit);
// marcher family: signed distance in world units (exact for sphere/cube, lower bound for tetra edges and the knot)
float shapeSdf (int shape, vec3 p, vec4 obj, vec4 spin);
```

The shape is an explicit argument (callers pass `uShape`), so the block does not
depend on any uniform name and the same call can draw a plain sphere where one is
wanted (the cage's top balls). `shapeHit` is a drop-in replacement for
`ray_sphere` with the same `vec2(t_enter, t_exit)` / `y < x` = miss contract,
so the analytic shaders change one call site plus their normal computation
(normals now come out of the hit instead of `normalize(p - c)`). `shapeSdf`
replaces `length(p - c) - r` inside the existing `smin` merges, which keep
working for every shape (soap-film merged cubes and knots are a feature, not a
problem).

The numeric constants (inscribe factors, tetra face normals, knot radii and
march factors) live **once**, as a JS table in `glsl_lib.js`; the GLSL
`#define`s are generated from it and `js/shapes.js` reads the same table for
picking, so the two languages cannot disagree.

## Capability matrix

| shader | geometry core | sphere | cube | tetra | knot |
|---|---|:-:|:-:|:-:|:-:|
| `analytic_layers` | analytic, nearest-3 layers, ≤61 objects | ✓ | ✓ | ✓ | — |
| `hollow_bubbles` | analytic membrane, outer + inner shell, ≤32 | ✓ | ✓ | ✓ | — |
| `thick_analytic` | analytic chord, depth sorted, 4 | ✓ | ✓ | ✓ | — |
| `thick_raymarch` | scene SDF, `smin`, 4 | ✓ | ✓ | ✓ | ✓ |
| `thick_chain` | scene SDF, `smin`, 3 hops, 4 | ✓ | ✓ | ✓ | ✓ |
| `multi_thinfilm` | scene SDF, `smin`, 6λ, 3 | ✓ | ✓ | ✓ | ✓ |
| `multi_fresnel` | analytic, own camera, 4 | ✓ | — | — | — |
| `thick_glass` | analytic, own camera, 4 | ✓ | — | — | — |
| `XdXXzB`, `ld3SDl`, `llsSDf` | Shadertoy originals | ✓ | — | — | — |
| `bench_*` | benchmark entries | ✓ | — | — | — |

Why the gaps:

* **knot in the analytic renderers — skipped.** Those shaders promise
  constant-bound, march-free work per pixel. A knot needs ~30 sphere-trace steps
  *per object*, i.e. ~1800 steps for `analytic_layers` at 61 objects. That is a
  different renderer, not a variant. The knot is therefore SDF-shader-only, and
  picking a knot while an analytic shader is active switches the shader to
  `thick_raymarch` (with the usual note).
* **`multi_fresnel` / `thick_glass` — phase 2.** Their analytic cores are
  sphere/cube/tetra capable, but they derive surface normals inline as
  `normalize (p - center)` at every shading branch (`pn0`/`pn1`,
  `front_n`/`back_n`), so adopting `shapeHit`'s enter/exit normal contract means
  rewriting each of those branches, and neither has a shared camera to validate
  picking against. Mechanical but wide — they keep the sphere default until it is
  done.
* **originals — never.** `ld3SDl` would be easy (its warped sphere is already an
  SDF) but the ports stay byte-faithful to Shadertoy; that is their value.
* **bench — never.** The benchmark compares *techniques* on one identical scene;
  letting geometry vary would make its numbers incomparable.

## Tasks

### 1. `js/caps.js` — one capability registry for both axes (new)

`js/scenes.js` and the new shape registry need the same operations. Extract
them, parameterised by axis, instead of copying the file:

```js
Caps.axis({ list, metaKey: 'scenes', paramName: 'uScene', nativeKey: 'nativeScene', fallback: ['own'] })
// -> { list, get, supported, supports, nativeOf, nativeShader, apply, paramVisible }
```

Entries carry `id`, `label`, `value` (the int written to the hidden param; a
negative value writes nothing), `native` (partner shader; `null` = never chosen
by fallback, the UI disables the button instead — that is how `own` behaves
today) and `hint`. `metaKey` doubles as the param restriction key
(`p.scenes: [...]` / `p.shapes: [...]`). `js/scenes.js` and `js/shapes.js` are
thin bindings: a list plus `Caps.axis(...)`.

### 2. `js/shapes.js` — the shape registry (new)

Four entries (`sphere`, `cube`, `tetra`, `knot`) plus the picking geometry:

```js
Shapes.hit(shape, rayOrigin, rayDir, objs, objOffset, spins, spinOffset) -> tEnter | -1
```

* bounding ball first, for every shape;
* cube / tetra — the same Rodrigues + `planeClip` sequence as the GLSL, from the
  same constants (module-level scratch arrays, no allocation per click);
* knot — the bounding ball, documented as an approximation (a knot tube sweeps
  most of its bounding ball, so the error is far smaller than a cube's would be).

### 3. `js/scene.js` — `Feeds.spin`

Per-index axis, rate and phase (hash spread, matching `makeCage`'s style,
rates alternate in sign), angle already advanced by `time`. Writes as many
entries as the buffer holds.

### 4. `js/camera.js` — shape-aware picking and selection

* `pickable()` also runs the `spin` feed into the matching `uSpin` buffer;
* the hit loop calls `Shapes.hit(...)` with the shader's current `uShape`
  instead of the inline ray/sphere solve (the cage's top balls stay spheres);
* `Cam.sel` gains a companion `Cam.selRot` (the selected object's axis/angle),
  refreshed by `updateSelPos()` and exposed through a new `camSelRot` feed. A
  selection without a spin (top balls) writes a zero axis.

### 5. `js/glsl_lib.js` — `GLSL.shape`, shape-aware halo

* the constants table, `spinMat`, `planeClip`, `boxHit`, `sdBox`, `sdTetra`,
  `sdKnot`, `shapeHit`, `shapeSdf`;
* `GLSL.selGlow` uses `shapeHit` with `uSel` + the new `uSelRot` var and the
  shader's `uShape`, so the rim glow hugs a cube's faces instead of floating
  around its bounding ball. A zero spin axis means "plain sphere" (the top
  balls);
* `analytic_layers`' local `selectionGlow` is replaced by `GLSL.selGlow` (it
  exists twice today only for historical reasons).

### 6. `shaders/*.js` — adopt the block

Per supporting shader: add `shapes` / `nativeShape`, the hidden `uShape` param,
the `uSpin` array and the `uSelRot` var, interpolate `${GLSL.shape}`, and swap
`ray_sphere(ro, rd, c, r)` → `shapeHit(uShape, ro, rd, obj, spin, nA, nB)` (or
`length(p-c)-r` → `shapeSdf(uShape, p, obj, spin)` in the marchers), taking the
normals from the hit.

`hollow_bubbles` gets the inner surface from the same shape scaled by
`(1 - uWall)` — identical semantics to today's `Ri = R * (1 - uWall)`, so the
`wall` slider keeps meaning "fraction of the size" for every shape. Its event
loop keeps the normal of the winning event, so `crossWall` no longer derives
normals from the centre.

`multi_thinfilm` gains `params` / `arrays` for `uShape` / `uSpin` and
interpolates `GLSL.raySphere` + `GLSL.shape` ahead of its own code; its warped
`sdf()` passes the warped point to `shapeSdf`.

### 7. `js/ui.js` + `index.html` — the third row

`shape · what it is` row under the scene row, same `active` / `alt` / `disabled`
styling, same note mechanism, global `curShape`, `__app.setShape` / `shape` /
`shapes` / `shapeOf` browser hooks. The scene and shape rows are one
implementation over an axis descriptor (registry, host element, current id,
noun, on-change hook), and `pick()` resolves both fallbacks in one pass, naming
each in the note. A param is visible only if both axes allow it.

### 8. `AGENTS.md` + `js/prompts.js`

AGENTS.md "concepts" grows the third selector and the rule that a shader
declares `shapes: [...]` like it declares `scenes: [...]`. `prompts.js` mentions
the shape block in the tech summary of the supporting shaders.

### 9. Optional, later — cage contact fidelity

Today the cage bounces on the bounding ball, so a cube visibly stops short of the
wall (its faces sit at `0.577 w`). An exact fix needs a fixed orientation per
object in the cage (the reflected trajectory is closed-form only for a constant
per-axis bound): freeze the spin to its phase in `uScene == 3`, compute each
object's rotated support per axis in `feedCageInside`
(`bound[axis] = cage - support(axis)`) and the faces touch. Deferred because it
trades the tumble for the contact, which is its own decision.

## Validation

Dev-only tooling lives in `tools_GPU/` (gitignored; `npm install` there brings
`glslang-validator-prebuilt-predownloaded`, `jsdom`, `puppeteer-core` and
`@sparticuz/chromium`, whose bundled Chromium renders WebGL2 through SwiftShader
without a GPU).

* **`check-glsl.mjs`** — glslang type-check of the exact fragment source the
  runner assembles (`buildFSHeader` + `buildUniformDecls` + source + footer)
  for every shader. `uShape` is a uniform, so one compile covers all shapes.
* **`check-shapes.mjs`** (node, no browser):
  * `Shapes.hit` agrees with a dense-sampled ground truth of the exact JS SDF
    along 10⁴ random rays per shape (enter `t` within 1e-4), including spun
    objects;
  * every vertex of a spun cube / tetra stays inside the bounding ball for all
    angles (the inscribe claim, tested); `spinMat` follows the right-hand rule;
  * `Feeds.spin` output is finite, axis-normalised and index-stable over time;
  * `Caps` fallbacks: for every (shader, shape) pair either the pair is supported
    or exactly one partner changes, and the reported note names both.
* **`check-ui.mjs`** (real `index.html` in the bundled Chromium): all 11 shaders
  × 6 scenes × 4 shapes select without an error; unsupported combinations fall
  back with a note; `alt` / `disabled` classes match the matrix; `uShape` is
  never shown as a slider; clicking a known cube under the cursor selects it
  and a click beside its bounding ball's inscribed face does not.
* **`render-check.mjs`** (same Chromium): renders every supporting shader ×
  shape at a small size, asserts no compile error and a non-blank, non-NaN frame,
  and writes screenshots for eyeballing: cubes and tetras tumble; the knot reads
  as a knot in the three marchers; `hollow_bubbles` shows a wall on all convex
  shapes; the halo hugs the shape; the knot click switches to `thick_raymarch`.

## Out of scope

* mesh/point-cloud assets, OBJ/glTF loading, any vertex or geometry pipeline —
  everything stays a fragment-shader ray tracer;
* mixed shapes in one scene (one global shape, like one global scene);
* per-shape materials, bevels/rounding (`sdRoundBox`) and shape morphing;
* the Shadertoy originals and the benchmark entries;
* making the knot pickable exactly in JS (bounding-ball approximation instead).
